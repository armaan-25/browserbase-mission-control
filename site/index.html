WHAT THIS IS

Stagehand v4 moved state management into the browser and let other clients attach alongside it. Two clients can now write to the same page, and CDP arbitrates nothing — so one client’s navigation silently destroys another’s work, with no error raised on either side.

Left is that collision, reproduced. Right is the same two clients behind a write lease: stagehand holds the page, playwright queues, and its navigation runs after the form is complete rather than through it. Deferred, never dropped.

The lease is ~140 lines with no browser dependencies — pageId is just a string key. Grants carry a TTL, because an automation client dying mid-write is the normal case and a plain mutex would wedge the page forever. Reads never queue.

Both panes are real Chromium pages on a real site — saucedemo.com, Sauce Labs’ public automation-practice app, using its own published demo credentials. Nothing is submitted; the collision happens while typing.

What is lost is not two text fields. Each pane starts from a session that took a login, three cart additions and a walk through to checkout to build. The second client’s navigation throws all of it away — and the first client never learns that it happened.

The frames here are screenshots of an actual run, replayed — every pixel came out of a browser that was genuinely being written to by two clients.
